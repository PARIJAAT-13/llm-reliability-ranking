# 4. Discussion

The empirical findings generated by the **LLM Reliability Ranking Framework** provide actionable insights into the interplay between prompt policy design, local inference latency, and physical hardware resource constraints.

---

## 4.1 Prompt Policy Decoupling vs. Hardcoded Adapter Formatting

A core architectural contribution of this framework is the complete decoupling of system prompting policies from benchmark adapter implementations. In standard evaluation harnesses, short-answer benchmarks often fail because instruction-tuned LLMs generate verbose conversational preambles (e.g., *"To answer your question, the capital of Japan is..."*). Benchmark implementations frequently attempt to fix this by inserting string parsing heuristics or regex matchers directly inside benchmark code.

Our framework demonstrates that injecting a standardized system prompt at the experiment configuration layer:
```text
You are solving a GAIA benchmark task.
Return ONLY the final answer.
Do not explain your reasoning.
Do not use markdown.
Output exactly the final answer.
```
achieves **100.0% exact-match accuracy** across `qwen2.5:7b`, `gemma2:9b`, and `mistral:7b` without modifying a single line of `GAIAAdapter` code. This architecture preserves clean benchmark evaluation logic while enabling researchers to evaluate different system prompt formulations as independent experimental variables.

---

## 4.2 Trade-offs Between Latency and Model Architecture

Empirical latency analysis reveals distinct operational performance profiles across the three executable candidate architectures:

1. **`ollama:qwen2.5:7b` (Mean Latency: 2.98s)**: Demonstrated the lowest average task latency among 7B models, with short-query latencies as fast as 1.3s (`gaia_001`).
2. **`ollama:gemma2:9b` (Mean Latency: 3.22s)**: Offered steady generation speed (1.9s–3.4s across tasks 1–4) despite its larger 9-billion parameter size, proving highly competitive in local deployment scenarios.
3. **`ollama:mistral:7b` (Mean Latency: 4.10s)**: Exhibited slightly higher mean generation time (4.10s) due to output token generation padding (`' Tokyo'`), but maintained 100% exact-match accuracy.

---

## 4.3 Operational Resilience Under Resource Bottlenecks

In local deployment environments, resource allocation failures represent the primary cause of evaluation pipeline crashes. When `llama3.1:8b` requested 26.4 GiB system RAM on a host with 15.7 GiB available memory, the local server returned an HTTP 500 internal server error. 

By categorizing `OllamaMemoryError` as a non-retryable exception (`is_transient = False`), the framework:
- Eliminated wasteful exponential backoff retries.
- Fast-skipped remaining benchmark tasks in 0.0 seconds.
- Recorded canonical `[SKIPPED]` execution and evaluation records.
- Completed the overall multi-model experiment matrix seamlessly in 105.63 seconds.

This fast-failing capability is essential for large-scale automated evaluation matrices operating over heterogeneous local model pools.
